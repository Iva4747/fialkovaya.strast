# Фиалковая страсть — обновлённый сайт

Готовая статическая версия для GitHub Pages. Серверная часть и установка Node.js не нужны.

## Посмотреть на компьютере

Распакуйте весь архив и откройте `index.html`. Для просмотра через локальный сервер можно запустить `python -m http.server 8000` из папки сайта и открыть http://localhost:8000.

## Опубликовать на GitHub Pages

1. Сохраните резервную копию текущего репозитория.
2. Загрузите содержимое папки сайта в корень репозитория `iva4747/fialko-vaya-strast`. В корне должен находиться `index.html`, а рядом — `style.css`, `app.js`, `images`, `fonts`, `articles` и `plants`.
3. Сохраните изменения коммитом. При существующей настройке GitHub Pages сайт обновится после завершения публикации.
4. Если публикация ещё не настроена: Settings → Pages → Deploy from a branch → main → /(root).

Старые `data.js` и `script.js` больше не используются. Новая версия не требует секретов и токенов.

## Что сохранено и добавлено

- 20 сортов, 33 названия деток и стартёров, 16 статей и 5 отзывов из исходного сайта.
- Отдельные страницы сортов и статей; страницы работают и без JavaScript.
- Поиск по названию, описанию и полному тексту статей, тематические категории, пункт «Все статьи», сброс фильтров.
- Выбранная категория и поисковый запрос записываются в адрес. Ссылкой на выборку можно поделиться.
- Избранные сорта сохраняются в текущем браузере. Синхронизации между устройствами нет.
- Мобильная вёрстка, навигация с клавиатуры, видимый фокус, учёт уменьшения движения.
- Локальные фотографии WebP и локальный шрифт Golos Text. Шрифты распространяются по OFL, лицензия в `fonts/OFL.txt`.

## Добавление статей

Все материалы хранятся в `content.json`. В массив `articles` добавьте объект, например:

```json
{
  "id": "wick-watering",
  "tag": "Уход",
  "title": "Заголовок новой статьи",
  "short": "Короткое описание для карточки",
  "text": "Первый абзац.\n\nВторой абзац.",
  "images": ["images/new-article.webp"]
}
```

`id` должен быть уникальным, состоять из латинских букв, цифр и дефисов. Существующие `id` менять не нужно: от них зависят адреса опубликованных страниц. `images` можно не указывать. Фотографии положите в папку `images`.

`tag` сопоставляется с категориями в словаре `CATS` в `build.py`. Новое значение, отсутствующее в словаре, создаст отдельную категорию.

После изменения содержимого выполните:

```sh
python build.py
```

Нужен Python 3; дополнительные библиотеки для сборки не требуются. Загрузите обновлённые HTML-файлы и фотографии в репозиторий. Перед публикацией проверьте новые материалы на телефоне.

Это файловое управление материалами. Административной панели в этой версии нет.

## Перенос из ВКонтакте

В архиве находятся только материалы, уже присутствовавшие в исходном репозитории. Новые публикации сообщества автоматически не импортировались. Для них нужны ссылки или выгрузка текстов и изображений; затем материалы можно добавить в `content.json` и пересобрать сайт. Источник каждой статьи не выдумывался: индивидуальные ссылки на публикации нужно добавить после получения исходников.

## Проверка

В Chromium проверены страницы на ширинах 320, 390, 768, 1024 и 1440 px: горизонтальной прокрутки на проверенных страницах нет. Проверены поиск, категории, сброс, сохранение выборки после перезагрузки, избранное, мобильное меню, локальные ссылки и изображения на всех 40 страницах. Ошибок JavaScript при проверке не обнаружено.

Публикация в удалённый репозиторий в этой поставке не выполнялась.
